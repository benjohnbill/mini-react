# 사람이 이름으로 데이터 흐름을 따라가도록 이름과 함수 규칙을 둡니다

코드 전체를 AI가 생성할 수 있으면, 모든 코드가 팀원에게 남이 짠 코드가 됩니다. 그래도 병합된 코드는 말로 설명할 수 있어야 하므로, 함수 본문을 열지 않고 이름과 시그니처만 따라가서 각 함수가 하는 일과 데이터 경로를 말할 수 있어야 한다는 기준을 둡니다. 함수는 단계와 대상으로 나누고, 이름의 형식은 Biome으로, 이름의 뜻과 함수 나누기는 리뷰로 판정합니다.

## 고려한 대안

- **줄 수 제한과 복잡도 규칙:** 수치는 단계와 대상이 섞였는지를 재지 못하므로 쓰지 않습니다.
- **`모듈_동사` 접두어(Pintos 팀의 규칙):** C에 네임스페이스가 없어서 생긴 방법입니다. TS는 `import`가 출처를 보여 주므로 `동사+목적어`만 씁니다.
- **호출자가 하나인 함수를 모두 합치기:** 코드 층은 줄지만 단계의 이름이 사라집니다. 단계에 이름을 붙이는 함수는 호출자가 하나여도 허용합니다.
- **규칙 없이 에이전트의 재량에 맡기기:** 생성할 때마다 이름과 경계가 달라지므로 쓰지 않습니다.

## 결과

- 이름의 뜻은 자동으로 판정할 수 없으므로, 코드를 작성하지 않은 새 세션의 검토와 사람의 리뷰가 필요합니다.
- 이 규칙은 나중에 CBM이나 Graphify로 호출 경로가 이름대로 보이는지 시험할 수 있습니다. 아직 측정하지 않았으므로 규칙의 근거로 삼지 않습니다.
