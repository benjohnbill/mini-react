# StateHistory는 View의 사본을 저장하고, 같은 내용을 거르는 일은 페이지가 맡습니다

`StateHistory`는 저장한 `View`의 목록과 현재 위치를 가집니다. 메서드 이름은 브라우저 History와 팀 테스트 시트를 따라 `push`, `current`, `back`, `forward`, `canBack`, `canForward`, `size`로 씁니다.

## 동작

- **저장:** `push`는 현재 위치 뒤의 `View`를 지우고 새 `View`를 끝에 더합니다. 브라우저에서 뒤로 간 뒤 새 페이지로 가면 앞으로 갈 페이지가 사라지는 것과 같습니다.
- **같은 내용:** `push`는 현재와 같은 내용의 `View`도 저장합니다. 바뀐 것이 없으면 저장하지 않는 일은 검증 페이지가 `diffViews`의 결과로 판단합니다(테스트 시트 80행).
- **이동:** `back`과 `forward`는 한 칸 옮긴 뒤 그 자리의 `View`를 돌려줍니다. 옮길 수 없으면 `null`을 돌려주고 현재 위치를 그대로 둡니다. 빈 이력에서도 같습니다.
- **사본:** 저장할 때와 돌려줄 때 모두 `structuredClone`으로 사본을 만듭니다. 밖에서 원본이나 돌려받은 `View`를 고쳐도 저장된 이력은 바뀌지 않습니다.

## 고려한 대안

- **`push`에서 같은 내용을 거르기:** `StateHistory`가 `View`를 비교해야 하므로 `diffViews`와 하는 일이 겹칩니다. 페이지는 어차피 `diffViews`를 부르므로 그 결과로 거릅니다.
- **사본 대신 `Object.freeze`:** 깊은 동결은 모든 자식을 따라가야 하고, 돌려받은 `View`를 고치려는 쪽이 오류를 만납니다. `View`는 작으므로 사본이 단순합니다.
- **CONVENTION.md의 `동사+목적어` 이름(`getCurrentView` 등):** 팀 테스트 시트가 이미 브라우저 History의 이름을 씁니다. 시트와 코드의 이름을 맞추고, 동사 표에 `push`, `back`, `forward`, `can`을 더했습니다.

## 결과

- 최대 개수(테스트 시트 69행, 선택)는 구현하지 않습니다. 테스트는 이유를 적은 `it.todo`로 남깁니다.
